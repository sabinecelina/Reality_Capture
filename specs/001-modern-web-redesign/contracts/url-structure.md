# Contract: URL Structure

**Phase**: 1 — Design
**Branch**: `001-modern-web-redesign`
**Date**: 2026-03-16

The URL structure is an external-facing contract. Changing URLs breaks inbound links, bookmarks, and search engine rankings. This document defines the canonical URL structure for the redesigned site and documents any deviations from the legacy Jekyll site.

---

### Blog Post URLs

**New canonical pattern**: `/blog/[slug]/`

Where `[slug]` is derived from the Markdown filename (e.g., `2025-03-01-cutting-edge-3dgs.md` → `/blog/2025-03-01-cutting-edge-3dgs/`).

| Post slug | New URL | Legacy URL |
|-----------|---------|------------|
| `2024-12-19-easy-introduction-nerf` | `/blog/2024-12-19-easy-introduction-nerf/` | `/general/2024/12/19/easy-introduction-nerf/` |
| `2025-03-01-cutting-edge-3dgs` | `/blog/2025-03-01-cutting-edge-3dgs/` | `/general/2025/03/01/cutting-edge-3dgs/` |
| `2025-06-01-difference-gs-nerf` | `/blog/2025-06-01-difference-gs-nerf/` | `/general/2025/06/01/difference-gs-nerf/` |

## Legacy URL Redirects

The legacy Jekyll blog URL structure (`/general/YYYY/MM/DD/slug/`) must redirect to the new canonical URLs to preserve inbound links and search engine rankings.

**Method**: A `_redirects` file for Netlify, or for GitHub Pages (which does not natively support server-side redirects), add a meta-refresh on a stub 404 handler or implement client-side redirects via `404.astro`.

**Redirect table** (301 Permanent):

```
/general/2024/12/19/easy-introduction-nerf/     →  /blog/2024-12-19-easy-introduction-nerf/
/general/2025/03/01/cutting-edge-3dgs/          →  /blog/2025-03-01-cutting-edge-3dgs/
/general/2025/06/01/difference-gs-nerf/         →  /blog/2025-06-01-difference-gs-nerf/
/general/2025/06/07/my-journey/                 →  /blog/2025-06-07-my-journey/
/general/2025/07/23/gentle-introduction-to-sfm/ →  /blog/2025-07-23-gentle-introduction-to-sfm/
```

**GitHub Pages implementation**: Generate stub HTML pages at legacy paths containing `<meta http-equiv="refresh" content="0;url=[new URL]">` and `<link rel="canonical" href="[new URL]">`. These are generated by Astro as static pages at build time.

## Asset URL Contract

All URLs under `/assets/` are **immutable** — the path of any existing asset must not change. This preserves links embedded in external sites, social shares, and the thesis content.

**Constraint**: All files currently in `assets/` (current repo) are placed in `public/assets/` in the Astro project. Astro copies `public/` verbatim to `dist/` with no path transformation.

**Verification**: A build-time check (linting step) confirms that all `src` and `href` attributes in the generated HTML that point to `/assets/` resolve to existing files in `public/assets/`.

## Blog Index URL

**Legacy**: `/blog/` was a Jekyll page that listed all posts by grouping them via Liquid.
**New**: `/blog/` is an Astro static page generated from Content Collections — exact same URL, behavior improved (sorted reverse chrono, better visual design).

No redirect needed for `/blog/`.
