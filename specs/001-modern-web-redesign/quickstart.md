# Quickstart: Modern Web Application Redesign

**Phase**: 1 — Design
**Branch**: `001-modern-web-redesign`
**Date**: 2026-03-16

This guide is for a developer (or Copilot agent) starting implementation of the redesigned site. It covers environment setup, project scaffolding, content migration, and verifying a working local build.

---

## Prerequisites

- **Node.js 20 LTS** (verify: `node --version`)
- **npm 9+** (comes with Node 20)
- **Git** — already set up for this repo

---

## 1. Scaffold the Astro Project

From the repository root (on branch `001-modern-web-redesign`):

```bash
# Install Astro with the portfolio/blog template as a starting point
npm create astro@latest . -- --template minimal --typescript strict --no-install
```

> **Note**: Use `.` to scaffold into the current directory. When prompted about existing files, skip overwriting `.git`, `specs/`, `.specify/`, `.github/`.

Then install dependencies and integrations:

```bash
npm install
npm install @astrojs/tailwind @astrojs/mdx @astrojs/sitemap tailwindcss lucide-astro
```

---

## 2. Configure Astro

Edit `astro.config.mjs`:

```js
import { defineConfig } from 'astro/config';
import tailwind from '@astrojs/tailwind';
import mdx from '@astrojs/mdx';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://www.sabineschleise.com',
  output: 'static',
  integrations: [
    tailwind(),
    mdx(),
    sitemap(),
  ],
  trailingSlash: 'always',
  markdown: {
    shikiConfig: {
      theme: 'agate',
    },
  },
});
```

Edit `tailwind.config.mjs`:

```js
export default {
  content: ['./src/**/*.{astro,html,js,jsx,md,mdx,svelte,ts,tsx,vue}'],
  darkMode: 'class',
  theme: {
    extend: {
      fontFamily: {
        sans: ['Inter', 'Quicksand', 'Arial', 'sans-serif'],
      },
      colors: {
        brand: {
          DEFAULT: '#1a365d',
          dark: '#0a2540',
        },
      },
    },
  },
};
```

## 4. Set Up Content Collections

Create `src/content/config.ts`:

```ts
import { defineCollection, z } from 'astro:content';

const blog = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    date: z.coerce.date(),
    categories: z.array(z.string()),
    description: z.string().optional(),
    draft: z.boolean().default(false),
  }),
});

const projects = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    teaser: z.string(),
    thumbnail: z.string(),
    order: z.number(),
    description: z.string().optional(),
  }),
});

export const collections = { blog, projects };
```

## 5. Migrate Blog Posts

Copy each `_posts/*.md` to `src/content/blog/`, then:
1. Remove the `layout:` frontmatter key
2. Replace all `{{ '/assets/...' | prepend: site.baseurl }}` occurrences with `/assets/...`
3. Replace Jekyll Liquid loops (e.g., the frame gallery `{% for f in site.static_files %}`) with static image lists or component props

Example frontmatter before (Jekyll):
```yaml
---
layout: page
title: "An easy introduction to NeRF"
date: 2024-12-19 10:00:00 +0100
categories: ["general"]
---
```

After (Astro):
```yaml
---
title: "An easy introduction to NeRF"
date: 2024-12-19
categories: ["general"]
---
```

## 7. Create Core Layouts

### `src/layouts/BaseLayout.astro`

```astro
---
interface Props {
  title: string;
  description?: string;
}
const { title, description = 'Homepage Sabine Schleise' } = Astro.props;
const canonicalURL = new URL(Astro.url.pathname, Astro.site);
---
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>{title} | Reality Capture</title>
    <meta name="description" content={description} />
    <link rel="canonical" href={canonicalURL} />
    <meta property="og:title" content={title} />
    <meta property="og:description" content={description} />
    <meta property="og:type" content="website" />
    <!-- Dark mode: must run before CSS to prevent FOUC -->
    <script is:inline>
      const stored = localStorage.getItem('theme');
      const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
      if (stored === 'dark' || (!stored && prefersDark)) {
        document.documentElement.classList.add('dark');
      }
    </script>
  </head>
  <body class="bg-white dark:bg-gray-950 text-gray-900 dark:text-gray-100 font-sans">
    <slot />
  </body>
</html>
```

## 8. Verify Local Dev Server

```bash
npm run dev
```

Open `http://localhost:4321/` — the home page should render without errors.

Run a production build and verify:

```bash
npm run build
npm run preview
```

Check that:
- [ ] Home page renders with video hero
- [ ] `/blog/` lists all 5 posts
- [ ] A blog post page renders with syntax-highlighted code
- [ ] `/projects/` shows all 4 project cards with thumbnails
- [ ] `/cv/` shows experience, education, and PDF download link
- [ ] Dark mode toggles correctly and persists on page reload
- [ ] Mobile menu works at 375px viewport width

## 10. GitHub Actions Deployment

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [001-modern-web-redesign]  # change to main after merge
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: withastro/action@v2
```

> **Note**: After the feature branch is merged to `main`, update the `branches` trigger to `[main]`.

## Constitution Note

The project constitution (`.specify/memory/constitution.md`) is currently an unfilled template. Before the implementation tasks are complete, the constitution should be ratified with at minimum:

1. **Principle I — Content-First**: All pages are statically generated from Markdown content; no server-side compute required.
2. **Principle II — Zero-JS Default**: Interactive JavaScript is added only where required (theme toggle, mobile navigation); all other rendering is build-time HTML.
3. **Principle III — Accessibility**: WCAG 2.1 AA is a non-negotiable gate on every PR.
4. **Governance**: Lighthouse CI gates block merges if any category drops below 90.
